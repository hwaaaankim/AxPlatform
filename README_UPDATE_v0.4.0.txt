AxPlatform v0.4.0 적용 안내 — 2026-10-20
기준 원본: 이번에 첨부한 AxPlatform.zip(v0.3.0)

1. 이번 파일의 의미
- 변경코드 ZIP: 이번 작업에서 추가·수정된 파일만 들어 있습니다.
  ZIP 안 AxPlatform 폴더의 내용을 현재 Eclipse 프로젝트 루트에 덮어씁니다.
  pom.xml끼리, src끼리, db끼리, docs끼리 같은 위치에 복사하세요.
- 전체소스 ZIP: 기존 코드와 이번 변경을 합친 전체 프로젝트입니다.
  새로 가져올 때 사용합니다. 이미 사용 중인 프로젝트는 변경코드 ZIP을 권장합니다.
- 실제 config/application-private.yml은 ZIP에 포함하지 않았습니다.
  현재 사용 중인 개인 설정 파일을 그대로 유지하세요. DB 비밀번호·API 키 재입력 불필요.
- 기존 DB·고객·표 데이터 삭제가 필요하지 않습니다. 삭제할 기존 소스 파일도 없습니다.
- 현재 개발 단계는 P1 기반 + 확장된 P2 일부입니다. 기획서 전체 기능의 출시 완료본은 아닙니다.

2. 적용 순서 — 직접 복사·HeidiSQL 실행
① 현재 프로젝트, DB, data/private 첨부 폴더를 백업하고 Spring Boot를 종료합니다.
② 변경코드 ZIP의 AxPlatform 안 파일들을 현재 프로젝트 같은 위치에 복사합니다.
③ HeidiSQL에서 사용하는 AxPlatform DB를 선택합니다.
④ db/manual/08_V004__guided_workspace.sql 전체를 복사해 실행합니다.
   기본 DB명이 AxPlatform이 아니면 파일 맨 위 USE `AxPlatform`만 실제 DB명으로 바꾸세요.
   V001~V003을 이미 실행한 환경 기준입니다. 이전 SQL을 다시 실행할 필요 없습니다.
   오류가 나면 그 지점에서 멈추세요. DDL은 자동 커밋되므로 전체가 롤백된다고 가정하지 마세요.
⑤ db/manual/09_VERIFY_V004.sql을 실행합니다.
   V004 기록 1개, ap_sheet_view 7컬럼, 신규 권한 4개·의존 5개를 확인하세요.
   기본 테이블은 33개에서 34개가 됩니다. 별도 추가 테이블이 있으면 총수는 달라집니다.
⑥ Eclipse에서 프로젝트 선택 → Refresh(F5).
   pom.xml 버전이 0.4.0으로 바뀌었으므로 Maven → Update Project 후 실행합니다.
   npm·React·프런트 개발서버는 필요하지 않습니다.
⑦ 브라우저에서 Ctrl+F5 후 /admin/login으로 접속합니다.
   기존 관리자 아이디·비밀번호가 유지됩니다. 최초 계정 생성 규칙도 변경하지 않았습니다.
⑧ 관리자 → 권한관리에서 고객 등급에 필요한 신규 기능을 배정하고 변경 검토 → 정책 적용합니다.
   신규 항목: 엑셀 파일 미리보기 / 엑셀 계산 열 설정 / 엑셀 분석 조회 / 엑셀 분석 보기 관리.
   의존 기능을 함께 확인하세요. 전체 교체는 기존 행 삭제 권한도 필요합니다.
   관리자 본인 업무 공간에서는 구현된 기능을 직접 검토할 수 있습니다.

3. 변경한 사용 흐름
- 로그인: 회원/관리자 탭, 일관된 입력·버튼·비밀번호 보기, 소셜 연결 상태 반영.
- 공통: 사이드 메뉴, 현재 업무 표시, 모바일 메뉴, hover/선택/등장/탭/모달 전환.
  운영체제 모션 감소 설정에서는 애니메이션을 끕니다.
- 각 페이지: 검은 오버레이와 대상 강조, 이전·다음, 닫기·다시 보지 않기·우측 아래 사용 안내.
  자동 숨김은 브라우저·계정·페이지별입니다. 다른 기기와 자동 동기화하지 않습니다.
- 엑셀: 시작 방법 → 자료 준비 → 편집·AI 검토 → 저장·데이터 보기.
  사진 / 대화 / XLSX·CSV / 직접 입력 중 선택한 방법의 도구만 표시합니다.
- 목록에서 기존 엑셀 열기는 편집 화면이 기본입니다. 질문을 처음부터 반복하지 않습니다.
- 업무별 목록 필터, 이름 검색, 정렬, 저장 상태, 원본 보관·재사용 동작을 유지합니다.
- 관리자 권한: 기능 선택과 등급 배정을 나란히 배치하고 검토·적용 순서를 표시합니다.
- Word/HWP/PPT/CRM/일정/프로그램은 요구사항 정리·AI 검토 범위입니다.
  지원하지 않는 최종 출력·운영 기능이 완성된 것처럼 표시하지 않습니다.

4. 실제 엑셀 사용 순서
① 엑셀·데이터 → 새 엑셀 만들기 → 직접 표 만들기.
② 이름 입력. 빈 표 또는 매출 기록/재고 관리 등의 열 구성 선택.
   구성에는 고객 데이터나 가짜 예시 행을 넣지 않았습니다.
③ 편집으로 이동 → 행 추가 → 셀 입력.
   열 머리글을 누르면 이름·형식·단위·너비·계산식 설정이 열립니다.
   열을 드래그하거나 이동 버튼으로 순서를 바꿀 수 있습니다.
④ 숫자 계산: 숫자 열을 선택하고 ‘○○ 넣기’로 [열ID]를 넣어 + - * / ( )로 작성합니다.
   예: [수량열ID] * [단가열ID]. 실제 열 ID는 선택 버튼으로 입력하세요.
   문자·임의 함수·JS·SQL은 계산식으로 실행하지 않습니다.
   빈 참조는 빈 결과, 0 나눗셈·순환·삭제된 참조·과도한 정밀도는 저장을 막습니다.
   계산 결과는 서버 저장 때 확정하며 숫자는 최대 15자리, 소수는 최대 12자리입니다.
⑤ 저장하고 데이터 보기 → 기준 열·집계 연산·숫자 열 선택 → 집계 확인.
   건수/합계/평균/최솟값/최댓값과 막대그래프, 정확한 값 표를 확인합니다.
   보기 이름을 정해 저장하면 같은 업무에서 다시 불러올 수 있습니다.
⑥ 데이터 XLSX 또는 빈 양식 XLSX 다운로드.
   빈 양식은 제목만 포함합니다. 내려받은 빈 양식의 새 행 수식 자동 채움은 제공하지 않습니다.
⑦ 작업 목록 → 해당 작업 열기 → 내용 수정 → 다시 저장.

5. 파일 가져오기
- XLSX 또는 쉼표 구분 CSV, 10MB, 최대 20열·데이터 200행.
- XLSX에서 여러 시트가 있으면 사용할 시트를 고릅니다. 첫 행은 제목으로 읽습니다.
- CSV는 UTF-8 또는 한글 Windows(CP949)를 직접 선택합니다.
- 열 연결 → 추가/전체 교체 → 중복·경고 확인 → 편집 초안에 넣기 → 셀 확인 → 저장.
- 전체 교체는 이 표의 데이터 행 범위이며 다른 업무를 바꾸지 않습니다.
- 원본 파일의 수식은 실행하지 않고 저장된 계산값만 읽습니다. 안내에 동의해야 반영 가능합니다.
- 원본 수식·서식·차트·그림은 가져오지 않습니다. 병합 셀, 오류 셀, 계산값 없는 수식은 안내 후 차단합니다.
- 새 표는 앞자리 0을 보존하기 위해 문자로 읽습니다. 숫자·날짜 형식은 확인 후 선택하세요.
- 동일 행 후보는 안내하고 자동 삭제하지 않습니다. 업무 키 기반 전표 중복 탐지는 미구현입니다.
- PDF·XLS·XLSM, 대용량 일괄 처리, 전체 Excel 함수는 지원하지 않습니다.

- Maven Java17 빌드·실행 JAR 패키징, H2 기반 서버 통합검증.
- 신규 수식·가져오기·집계·권한·버전·재시도 검증.

  실제 브라우저 육안·모바일 터치·한글 IME·Excel/LibreOffice 재열기 검수는 남아 있습니다.

- 자세한 단계·수행 결과·출시 전 남은 범위는 docs/V004_STAGE_AND_SCOPE.txt와 docs/V004_VALIDATION.txt를 확인하세요.
