관리자 초기화·복구 경계
1. 최초 DB의 INITIAL_ADMIN 잠금 행을 FOR UPDATE로 잠그고 계정·시험 공간·마커를 한 트랜잭션에 생성합니다.
2. 재시작 시 기존 해시·역할·상태를 변경하지 않습니다. 프로필 전환도 동일합니다.
3. 완료 마커는 있는데 관리자 자격증명이 없거나 account_id가 다르면 자동 재생성을 막습니다.
4. admin ID 충돌 시 관리자 역할 승격이나 기본 비밀번호 덮어쓰기를 하지 않습니다.
5. 정상 비밀번호 변경은 /admin/password에서 현재 비밀번호를 확인한 뒤 PasswordEncoder.encode로 저장합니다.
   security_version을 올려 다른 세션의 다음 요청도 차단합니다.
6. 분실·DB 수동 삭제 복구:
   앱을 중지하고 HeidiSQL에서 관리자 관련 테이블·마커·소유 공간 상태를 읽기 전용으로 확인합니다.
   DB 백업이 있으면 일관된 백업으로 복구합니다. 마커를 삭제하거나 password_hash에 평문을 넣지 않습니다.
   백업이 없으면 이후 제공할 별도 복구 절차/해시 생성 도구로 본인 소유를 확인하고 새 비밀번호를 적용해야 합니다.
   현재 버전에는 비밀번호 분실 복구 UI/복구 도구가 없습니다. 복구 성공을 주장하지 않습니다.
7. 현재에는 관리자 삭제/정지/강등 API가 없으므로 일반 화면에서 마지막 관리자를 변경할 수 없습니다.
   향후 관리자 역할 관리에는 마지막 활성 최고관리자 보호 검수를 추가합니다.
