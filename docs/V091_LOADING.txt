AxPlatform 0.9.1 공통 로딩 동작 및 검증 / 2026-10-25

구현
loading.js의 beginLoading/withLoading을 공통 사용합니다.
request.js는 요청 전부터 전송/응답 본문 해석까지 로딩을 유지하고 finally에서 반환합니다.
큰 JSON 직렬화와 브라우저 내 표 작업 전에 화면 갱신 기회를 줍니다.
성공·HTTP 오류·네트워크 실패·JSON 해석 실패·Abort·CSRF 확인 실패 모두 종료 경로를 사용합니다.
네트워크 요청을 임의로 재전송하거나, 실패한 저장을 성공으로 표시하지 않습니다.

겹치는 작업은 토큰별로 관리하며 단일 오버레이를 공유합니다.
한 요청이 끝났다고 남은 요청의 로딩을 숨기지 않습니다. 이전 해제 타이머가 새 작업을 숨기지 않습니다.
짧은 작업은 약 160ms 표시로 깜빡임을 줄입니다. 완료 API 응답 자체를 이 시간만큼 지연시키지 않습니다.
이후 호출자의 동기 DOM 갱신도 끝난 뒤 화면이 열립니다. 처리율·완료 예상 시간을 꾸미지 않습니다.

표시와 조작
- 흐린 전체 화면 + 흰색 카드 + 현재 동작 + 애니메이션 막대. 8초 이후 경과 시간 표시.
- 처리 중 신뢰된 사용자 클릭/입력/제출과 배경 스크롤을 차단합니다. 브라우저 새로고침 등은 유지합니다.
- manual popover로 기존 자료 선택/설정 dialog 위에 표시합니다. 미지원 환경은 열린 dialog 안에 표시합니다.
- 입력 포커스를 로딩 카드로 강제 이동하지 않습니다. 진행 상태/aria-busy를 제공하고 기존 상태로 복구합니다.
- 모바일 크기와 reduced-motion 설정을 지원합니다. 외부 CSS/JS/CDN 의존성 추가 없음.
- 일반 내부 링크/폼의 실제 이동만 안내합니다. AJAX가 preventDefault한 제출, 다운로드/blob/API 링크,
  새 탭·외부 링크·현재 문서 내 앵커 이동에는 가짜 페이지 이동 오버레이를 남기지 않습니다.
- 뒤로가기 복원(pageshow), 페이지 이탈, 미저장 경고로 이동이 취소된 경우 이동 표시를 해제합니다.
  오래 걸리는 일반 페이지 이동은 '로딩 표시 닫기'로 표시만 닫을 수 있습니다. API 작업 취소 버튼이 아닙니다.

작업별 연결
- 업로드/서버 미리보기/시트 초안 변환을 하나의 바깥 작업으로 감싸 중간에 오버레이가 사라지지 않습니다.
- 미리보기 페이지/시트 전환과 가져오기 적용, 편집 표 검색/정렬/페이지 이동/시트 구성 변경.
- 저장·되돌리기, 데이터 센터의 서버 조회/정렬/집계/계산 열, 브라우저 그래프 작성.
- raw fetch를 쓰는 원본 XLSX 및 현재 보기 XLSX/CSV도 blob 수신까지 전체 동작을 감쌉니다.
- 자동 수식 계산과 목록 SSE 갱신은 blocking:false 작은 진행 표시.
- AI polling은 loading:false, 기존 작업 상태/취소 기능을 계속 사용합니다.
- 직접 입력 중에는 자동 계산이 입력을 가로막지 않습니다. 사용자가 실행한 저장/계산은 전체 표시입니다.

재사용
await withLoading('사용자에게 보일 동작명', async task => { ... });
task.update('다음 처리 단계'); 로 단계명을 갱신할 수 있습니다.
request(url, { loading: '동작명' }) 또는 loading: { label: '동작명', blocking: false }.
독립된 자동 상태 확인에만 loading:false를 사용합니다. 전역 fetch를 덮어쓰지 않습니다.
import 경로의 캐시 키는 모두 0.9.1로 통일해야 단일 로딩 상태가 공유됩니다.
renderWorkbookImport(...).apply()는 오버레이가 그려진 뒤 실행하는 Promise<boolean>입니다.
프로그램에서 완료 결과가 필요한 경우 await를 사용합니다. 기존 화면의 단계 이동은 완료 콜백으로 연결됩니다.

실행한 검증
- 공통 로딩 DOM 19개: 선행 표시, 응답 본문 대기, 중첩 요청, 예외·취소·해제 타이머,
  자동 계산/사용자 처리 우선순위, 포커스, 배경 스크롤 차단, 열린 dialog 대체 표시,
  AJAX 제출 구분, 일반 폼 이동, 뒤로가기 복원.
- 데이터 센터 DOM 17개, 순차 흐름 14개, 다중 시트/사진·AI 14개, 수식 UI 13개 통과.
- 실제 첨부 파일 기반 큰 통합문서 DOM 15개 통과: 두 시트 24,987행/16,167행,
  96,827개 수식/입력값 보존, 미리보기·편집 페이지, 정렬, 저장/재열기.
- 업무 목록 데이터 센터 진입 검사 통과.
- Java UI 계약 테스트 1개 통과(기존 24페이지 렌더링/검사), 24페이지 DOM 공통 계약 통과.
- JavaScript 37모듈 문법 검사 통과. 캐시 키 0.9.1 일치 확인.
- ZIP 파일 목록·CRC·SHA-256 검증 후 제공.

검증 범위 구분
DOM은 Happy DOM과 로컬 모의 응답, 서버 렌더는 Spring/H2입니다.
운영 DB·유료 OpenAI를 호출하지 않았으며 Java 업무 로직/DB 구조를 변경하지 않았습니다.
0.9.0의 서버 전체 134개 회귀 결과와 이번 UI 변경 검증을 구분합니다. 전체 134개를 다시 실행한 것은 아닙니다.
실제 Chrome/Safari 픽셀·blur 합성·실기기 입력 차폐 검수는 실행 환경 제약으로 미실행입니다.
실제 브라우저 검수 없이 화면의 완전한 시각적 일치를 검증했다고 표현하지 않습니다.
