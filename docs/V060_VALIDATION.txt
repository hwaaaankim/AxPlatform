이번 핵심 검증

- 지정 시트만 단일 AI 적용, 다른 시트 데이터 보존.
- 사진별 제안 선택 적용, 준비되지 않은 시트 거부, 권한 부족 시 프로젝트/시트 모두 롤백, 멱등 재호출.
- 실제 AiService 비동기 처리 + 테스트 HttpClient로 사진 2개 처리. 사진별로 원본 1개만 전달.
  각 read_current_sheet 결과의 ID가 지정 대상과 일치. 자동 적용 없이 기존 데이터 유지.
  생성 4회가 round_no 0/1/6/7로 별도 기록되고 입력 400/출력 80 fixture 토큰으로 합산된 뒤 명시 일괄 적용.
- 여러 시트/빈 시트/한글·특수문자 이름 XLSX 내보내기와 다시 읽기. 모든 시트의 빈 양식 처리.
- 계산값 없는 수식, Excel 오류 셀, 계산값만 있는 수식, 숨김 시트, 병합 범위, 객체만 있는 시트, 암호/형식 오류, 긴 열 제목.
- 이미지 구조 손상·픽셀 한도 검사 및 정상 PNG/문자 입력.
- 미저장 셀을 유지한 시트 전환, 복제/이동/삭제/전체 취소, 전체 통합문서 저장 API.
- 모든 가져오기 시트 목록, 실패/숨김 기본 제외, 기존 시트 보존 및 중복 이름 자동 구분.
- 등록한 사진별 대상 목록, 개별 제외 시 원본 보존, 시트 준비 후 자동 생성 요청 없음.
- 사진별 성공/실패 이유 표시와 성공 시트만 적용, 분석 시트 ID 전달.
- 기존 회원·권한·폼·날짜·파일 선택/제거·업로드 부분 실패·내 자료·관리자 진단·페이지 안내 회귀 검사.

실행 방식
이 환경에서는 Maven의 Java 네트워크 의존성 해석이 실패하여 Maven Central에서 확보한 프로젝트 버전의 JAR로 검증했습니다.
JavaCompiler API(--release 17, -parameters), JUnit Console 6.0.3, Happy DOM 15.11.7을 사용했습니다.
마지막 전체 서버 검사 85개가 성공했으며, 이전 검사에서 발견한 템플릿 캐시 버전 누락을 수정 후 재검증했습니다.
이 환경에서 mvn clean package 성공을 확인했다고 주장하지 않습니다. 일반 개발 환경의 재현 절차는 qa/README.txt 참고.

검증 경계
사용자 MariaDB, 사용자 D드라이브 원본, 실제 API 키를 사용하지 않았습니다. 유료 생성 요청은 보내지 않았습니다.
사진 판독 품질·현업 Excel 파일 호환·실제 사용량/청구는 유효한 계정과 실제 자료로 확인해야 합니다.
Happy DOM은 실제 Chrome/Edge의 픽셀·터치·IME 검수가 아닙니다. 실제 브라우저 시각 검수와 Windows/Eclipse 실행은 미실행입니다.
XLSX 내보내기/읽기 자동 검사는 실제 Microsoft Excel 재열기 검사를 대체하지 않습니다.

설정/DB 변경
추가 SQL, 설정파일 수정, 실제 키 변경, 기존 원본 이동은 없습니다.
