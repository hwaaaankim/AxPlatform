AxPlatform 개발 구조와 다음 단계 / 0.7.0

현재 구현
- 공통 계정/권한/사업 범위, 공유 DB와 기기별 파일 보관, 활동·AI 사용량 기록 구조를 사용합니다.
- 엑셀 작업은 다중 시트 판독 → 단계별 준비 → 편집/계산 미리보기 → 저장 → 집계·재조회 흐름입니다.
- 단계 정의는 step-progress.js, 업무 진행은 workflow-flow.js, 업무별 질문은 workflow-guide.js로 나눕니다.
- 기본정보는 작업 식별/AI 조건, 참고자료는 원본 보관, AI 원본 선택은 실제 외부 전송 범위입니다.
- 이 세 역할을 서로 다른 단계와 짧은 안내로 구분합니다.
- 파일 재사용·프로젝트 전용 자료·계정별 저장·관리자 파일 관리 구조를 계속 사용합니다.

확장 원칙
1. 신규 업무도 source → basics → review → edit → finish의 진행/수정 구조를 재사용합니다.
2. 실제 파일 생성이나 외부 시스템 실행 전 결과 미리보기·적용 범위·명시적인 실행을 구분합니다.
3. 원본 식별자는 기존 AssetService, 사용 권한은 AccessService를 통과합니다.
4. 활동과 비용은 기존 ActivityRecorder/AI 미터링 경로에 기록합니다.
5. 편집 제안은 기준 버전을 보관하고 적용 시 다시 검사합니다.
6. 파일 판독 불가, 일부 누락, 지원하지 않는 객체를 성공으로 숨기지 않습니다.

후속 개발이 필요한 영역
- 원본 Excel 함수·피벗·차트·조건부서식·복잡한 서식의 완전한 보존/재계산.
- 수백만 행 이상 데이터의 서버 쿼리 기반 표 편집과 스트리밍 내보내기.
- WORD/HWP/PPT의 실제 파일 생성, CRM/일정/APP의 실행 기능.
- 실제 운영 서버의 동시 사용자 부하와 MariaDB 환경에서의 성능 검증.
현재 버전을 이 후속 범위까지 완성된 서비스로 표시하지 않습니다.
