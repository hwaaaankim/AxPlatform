AxPlatform 0.7.0 적용 안내
2026-10-25 / 0.6.1 프로젝트에 덮어쓰는 변경 파일 패치

1. 적용
- 실행 중인 AxPlatform을 종료합니다.
- ZIP의 pom.xml, src, docs, qa를 기존 pom.xml이 있는 프로젝트 루트에 덮어씁니다.
- config/application-private.yml 및 사용 중인 dev/test 개인 설정을 그대로 사용합니다.
- Eclipse에서 프로젝트 Refresh → Maven / Update Project → Project / Clean 후 실행합니다.
- 브라우저에서 Ctrl+Shift+R(Windows), Cmd+Shift+R(Mac)로 새로고침합니다.
- DB 스키마 변경이 없어 새 SQL을 실행할 필요가 없습니다. 기존 DB와 업로드 자료는 유지합니다.

2. 엑셀 가져오기
시작 방법 → 자료·시작 설정 → 기본정보 → 내용 확인 → 편집·검토 → 저장·보기
- XLSX/CSV 파일 1개를 선택하면 원본 등록과 시트별 미리보기가 시작됩니다.
- 시트 탭으로 미리보기를 바꾸고, 가져올 시트를 선택합니다. 숨김 시트는 기본 미선택입니다.
- 읽기 불가 시트는 이유를 표시하고 선택할 수 없습니다. 실패한 업로드로 빈 편집기에 들어가지 않습니다.
- 파일은 자동으로 현재 작업의 원본으로 연결됩니다. 별도의 첨부 선택은 필요하지 않습니다.
- 기본정보에는 작업 이름과 선택적인 AI 조건만 표시합니다. 답변은 AI 제안에 사용되며 원본 셀을 바꾸지 않습니다.
- 내용 확인 후 편집하면 선택한 모든 시트의 데이터가 표시됩니다.
- 기존 프로젝트에 가져오는 경우 기존 시트를 유지하고 새 시트로 추가합니다. 미리보기에 이 범위를 표시합니다.
- 업로드 원본의 등록 상태와 시트 가져오기 상태는 구분됩니다. 미리보기 재시도는 이미 등록한 원본을 사용합니다.

3. 돌아가기와 재편집
- 각 단계의 이전 버튼, 위 단계 메뉴, 편집 화면의 자료/기본정보/내용확인 아이콘을 사용합니다.
- 브라우저 뒤로/앞으로에도 단계 URL을 반영합니다. 진행 중인 입력을 같은 화면에서 유지합니다.
- 내용 확인의 항목 수정 버튼은 해당 질문으로 바로 이동합니다.
- 앞 단계로 갔다가 다음으로 돌아올 때 이미 가져온 시트를 다시 추가하지 않습니다.
- 새로고침·창 닫기는 서버 저장과 다릅니다. 큰 표는 전체 시트 저장 후 닫으세요.

4. 큰 표 편집
- 100행씩 표시하며 페이지 번호로 마지막 행까지 이동합니다. 화면에 보이지 않는 행도 저장됩니다.
- 전체/열별 검색, 오름차순·내림차순, 보기 초기화를 제공합니다.
- 정렬·검색은 보기 설정으로 저장됩니다. 원본 행 순서·행 ID를 유지하고 편집은 실제 해당 행에 적용합니다.
- 여러 셀 붙여넣기는 보기 초기화 후 사용합니다. 정렬/필터 상태에서 다른 원본 행을 덮는 일을 방지합니다.
- 머리글을 누르면 이름·형식·너비·단위·숫자 표시·소수 자릿수·계산식을 조정할 수 있습니다.
- 계산 열은 숫자 열의 [열ID]와 + - * / ( )를 지원합니다. 계산 미리보기는 저장 전에 결과를 확인합니다.
- 조회/수정/행 삭제/수식 권한 및 버전 충돌 검증을 유지합니다.
- XLSX 내보내기는 검색으로 숨겨진 행도 포함한 전체 데이터입니다.

5. 사진·대화·직접 입력과 다른 업무
- 직접 입력: 빈 표/기본 구성 선택 → 이름·선택 조건 → 확인 → 편집.
- 사진: 사진 선택·개별 제거 → 시트 준비 → 기본정보 → 확인 → AI 전송 확인.
- 대화: 짧은 요청 → 이름·선택 조건 → 확인 → AI 검토. API 전송·적용은 자동 실행하지 않습니다.
- WORD/HWP/PPT/CRM/CALENDAR/APP도 자료 → 기본정보 → 내용 확인 순서를 공유합니다.
- 참고자료는 작업에 보관하는 원본입니다. 연결만으로 표나 답변이 바뀌지 않습니다.
- AI에 전송할 자료는 AI 검토에서 별도로 선택합니다.
- 큰 표의 AI 편집은 원본 데이터 행 번호로 범위를 지정합니다. 최대 200행·4,000셀·셀 내용 80,000자입니다.
- 범위 밖 행과 기존 열 구성을 유지합니다. 범위 제안으로 행 순서·개수·열 구성을 바꾸려 하면 적용을 거부합니다.

6. 실제 지원 범위
- 업로드: 압축 파일 10MB, 해제 후 전체 128MB/개별 구성요소 64MB, 구성요소 1,000개.
- 프로젝트: 최대 20시트, 시트당 100열/50,000개 데이터 행/100만 셀, 전체 200만 셀/저장 JSON 14MB.
- 물리 셀은 시트당 200만 개까지 검사합니다. 값이 없는 끝부분 서식만으로 행을 늘리지 않습니다.
- 첫 행은 열 제목입니다. 빈 제목·긴 제목의 원문을 보존하고 편집용 이름을 별도로 사용합니다.
- 원본 수식은 저장된 계산 결과로 가져옵니다. 원본 Excel 함수/외부참조/매크로를 실행하거나 재계산하지 않습니다.
- 캐시가 없는 수식은 #N/A와 위치·해결 방법, Excel 오류 값은 원래 오류와 위치를 표시합니다.
- 미리보기는 셀 값·날짜·RGB 글자/배경색·굵기·가로 정렬·지원 범위의 병합을 표시합니다.
- 편집기는 병합을 셀 단위로 풀어 보여 주며, 병합 정보는 저장/내보내기에 보존합니다. 구조 변경 시 유지할 수 없는 병합은 해제합니다.
- Excel 원본의 테마·조건부서식·테두리·인쇄설정·차트/그림·피벗을 완전히 재현하는 엔진은 아닙니다.
- 차트/그림 객체는 가져오지 않고 시트별 사유를 표시합니다. 차트 전용 시트는 제외합니다.
- 숫자는 기존 15자리 정밀도 정책을 유지하며 식별번호의 앞자리 0은 문자로 보존합니다.
- 이 버전은 비엑셀 업무의 실제 DOCX/HWP/PPT 생성, CRM/일정 실행 엔진을 새로 구현하지 않습니다.

7. 개발 환경
- 큰 파일을 다룰 때 Eclipse Run Configurations / Arguments / VM arguments에 -Xmx1024m을 지정할 수 있습니다.
- 기존 per-device 파일 저장과 공유 DB 설정을 유지합니다. 다른 PC의 원본이 없더라도 저장된 표 데이터는 DB에서 읽습니다.
- 실제 운영 MariaDB와 유료 OpenAI API에 연결한 검증은 하지 않았습니다. 검증 상세는 V070_VERIFICATION.txt를 참고하세요.
