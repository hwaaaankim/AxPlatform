AxPlatform 0.6.1 — DB 공유 / PC별 원본 파일 보관
적용 기준: 0.6.0 다중 시트 패치가 적용된 프로젝트

1. 적용
- 실행 중인 AxPlatform을 종료하고 프로젝트 소스를 백업합니다.
- ZIP의 pom.xml, src, qa, docs 등을 현재 pom.xml이 있는 프로젝트 루트에 그대로 덮어씁니다.
- config/application-private.yml은 기존 파일 그대로 사용합니다. 이 ZIP은 개인 설정을 포함하거나 덮어쓰지 않습니다.
- Eclipse에서 프로젝트 Refresh(F5) → Project > Clean → Run 합니다.
- 브라우저를 새로고침합니다. 정적 파일 버전은 0.6.1입니다.
- 추가 SQL 없음. 기존 V005가 적용된 DB에서 사용합니다. 10번/12번 SQL을 다시 실행하지 않습니다.
- 사무실 폴더, storage-volume.id를 집이나 Mac으로 복사할 필요가 없습니다.

2. 실제 동작
- 사무실 Windows / 집 Windows / Mac이 같은 서버 DB에 접속합니다.
- DB의 프로젝트·시트·셀·자료 목록은 공유합니다. 파일 원본은 각 실행 PC에 따로 저장합니다.
- 새 PC의 저장 폴더는 자동으로 생성합니다.
- 현재 PC에 원본이 없어도 로그인·목록 조회·기존 프로젝트/시트 편집은 가능합니다.
- 내 자료, 관리자 자료, 작업 첨부, 원본 선택, AI 원본 선택에서 현재 PC의 파일 상태를 표시합니다.
- 없는 원본의 미리보기는 ‘파일 없음’으로 표시합니다. 해당 원본의 다운로드·AI 해석·엑셀 다시 가져오기는 교체 후 가능합니다.
- 원본 선택창은 파일이 없는 항목을 보여 주되 사용 선택을 막고 교체 버튼을 제공합니다.
- 내 자료 또는 작업 첨부에서 ‘파일 교체’ → 파일 1개 선택 → ‘이 PC에 저장하고 교체’.
- 같은 자료 ID와 작업 연결을 유지합니다. 사진끼리(PNG/JPG), 표끼리(XLSX/CSV), TXT끼리 교체할 수 있습니다.
- 파일 이름·크기·버전·원본 경로 정보는 공유 DB에서 변경되므로 다른 PC에도 반영됩니다.
- 새 파일의 실제 바이트는 교체한 PC에만 존재합니다. 다른 PC에서는 그 새 원본이 ‘파일 없음’으로 표시됩니다.
- 교체된 원본이 이미 만든 셀/시트 데이터를 자동으로 다시 계산하거나 덮어쓰지 않습니다. 필요하면 다시 가져오거나 AI 검토하세요.
- 교체 전 원본에 대한 미적용 AI 제안은 만료 처리합니다. 실행 중인 AI가 해당 원본을 사용하면 완료/취소 후 교체합니다.
- 이미 저장·적용된 표와 프로젝트 내용은 유지합니다.

3. 자동 경로
- Windows에 D드라이브가 있으면: D:/AxPlatform/dev (test 프로파일은 D:/AxPlatform/test)
- Windows에 D드라이브가 없으면: 사용자 홈/AxPlatform/dev
- macOS: /Users/사용자이름/AxPlatform/dev
- Linux: 사용자 홈/AxPlatform/dev
- 기존 회원별/7개 업무별/사업별/프로젝트별/용도별/날짜별 폴더 분류는 그대로입니다.
- 관리자 > 회원 자료·용량 > 실제 저장 루트/실제 저장 경로에서 현재 실행 PC의 경로를 확인합니다.
- AX_STORAGE_ROOT가 있거나 private에 ax.storage.root가 있으면 그 경로를 우선합니다.
- PC별 모드에서 Mac/Linux가 Windows 드라이브 경로를 받으면 사용자 홈의 기본 경로로 전환합니다.
- 로그 기본값: 사용자 홈/AxPlatform/logs/application.log. AX_LOG_ROOT로 바꿀 수 있습니다.
- ‘현재 PC’란 AxPlatform Java 프로그램을 실행한 컴퓨터입니다. 브라우저만 다른 PC에서 열면 파일은 서버 실행 PC에 저장됩니다.

4. 설정 확인이 필요한 경우
이번 application.yml의 ax.storage.binding-mode는 per-device이며 dev/test root 기본값은 auto입니다.
개인 설정이나 Eclipse VM 옵션에 별도 값이 있으면 그것이 우선할 수 있습니다.
기존 오류가 계속되면 개인 설정의 중복 키를 만들지 말고 기존 ax > storage 아래의 값을 확인하세요:
  binding-mode: per-device
  root: auto
필요한 경우에만 위 두 값을 적용합니다. DB 접속 정보·API 키는 바꾸지 않습니다.
ax.storage-root(하이픈)는 구버전 파일 경로, ax.storage.root(점)는 새 회원별 파일 경로입니다.

5. 용량·삭제·관리 범위
- 용량은 공유 DB에 등록된 자료의 논리적 총 용량입니다. 현재 PC에서 파일이 없어도 계산에 포함됩니다.
- 교체하면 기존 파일 크기를 빼고 새 파일 크기를 반영합니다. 다른 회원 자료는 회원이 교체할 수 없습니다.
- 영구 삭제는 공유 DB의 자료 연결을 해제하고 현재 실행 PC의 파일을 제거합니다.
- 다른 PC의 로컬 디스크 파일은 원격으로 지우지 않습니다. 교체/삭제 전의 오래된 파일이 다른 PC에 남을 수 있습니다.
- 관리자는 모든 회원의 DB 자료와 현재 실행 PC의 파일 경로·존재 여부를 관리합니다. 꺼져 있거나 접속하지 않은 다른 PC 디스크를 관리하는 기능은 아닙니다.
- 업로드 원본이 없다는 이유로 DB 프로젝트·셀 데이터를 삭제하거나 빈 파일로 대체하지 않습니다.

6. 기존 V005 단일 저장소 안내와의 관계
- per-device에서는 ap_storage_binding 경로/볼륨 불일치로 시작을 중단하지 않고, 공유 바인딩 행도 바꾸지 않습니다.
- V005 스키마 검사·회원 소유권·자료 범위·CSRF·파일 형식/크기·무결성 검사는 유지됩니다.
- 단일 서버에서 저장소 일치를 강제하려면 binding-mode: strict를 명시할 수 있습니다. 이 경우에만 V005 이전 절차/12번 SQL 안내가 해당됩니다.
- 이전 버전으로 되돌리면 단일 저장소 검사 때문에 다른 PC에서는 다시 실행이 막힐 수 있습니다.
