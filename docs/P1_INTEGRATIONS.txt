AxPlatform 0.2.0 / 가입·발송 연동 설정
실제 입력 파일은 프로젝트 루트/config/application-private.yml입니다.
config/application-private.example.yml의 전체 구조와 README_UPDATE_v0.2.0.txt를 비교하세요.
입력 조건을 갖췄다는 표시와 실제 제공자 연결 성공은 다릅니다. 본인 실수신·실로그인 확인이 필요합니다.
기본 브라우저 주소를 http://localhost:8080으로 통일합니다. 127.0.0.1로 로그인한 뒤 localhost로 콜백하면 세션이 달라질 수 있습니다.

A. 공통
ax.public-base-url: 'http://localhost:8080'
ax.auth.otp-secret: 32자 이상의 무작위 개인 비밀값. CHANGE_ME 금지.
ax.auth.registration-enabled: 처음 false → 이메일/SMS 설정 후 true → 앱 재시작.
이메일·SMS 인증이 실패하면 완료 처리하지 않습니다. 응답·로그·DB에 원문 OTP를 저장하지 않습니다.
OTP 6자리/5분/재전송 60초/오답 5회 종료/가입 증명 30분/목적·대상·원래 세션 묶음/가입 시 한 번 소비.
메일·문자 요청 제한은 DB에 저장되어 앱 재시작으로 초기화되지 않습니다.

B. 인증 메일: SMTP
메일 제공자에서 SMTP를 사용하도록 준비합니다. 제공자가 요구하면 2단계 인증과 앱 비밀번호를 발급합니다.
개인 파일의 기존 ax.integrations.smtp: 블록에 입력합니다.
enabled: true
host: '제공자의_SMTP_호스트'
port: 587
username: 'SMTP_로그인_아이디'
password: 'SMTP_비밀번호_또는_앱_비밀번호'
from: '검증한_발신_이메일'
auth: true
starttls: true
starttls-required: true
ssl: false
이는 587/STARTTLS 예입니다. 제공자가 465/SSL을 지정하면 port: 465, starttls: false, starttls-required: false, ssl: true로 바꿉니다.
발신 도메인 검증·발신 권한·차단/스팸 처리 등은 선택한 제공자에서 확인합니다.
현재 SMTP 어댑터는 연결/쓰기/읽기 제한 시간을 지정하고 TLS 인증서의 호스트 확인을 켭니다.
메일 접수 후 도착을 보장하지 않으므로 본인의 수신함/스팸함과 제공자 기록을 확인하세요.
공식 JavaMailSender 안내: https://docs.spring.io/spring-framework/reference/integration/email.html

C. 휴대전화 문자: SOLAPI
SOLAPI 계정에서 문자 발송 준비 → 사용할 발신번호 등록/인증 → API Key/API Secret 발급 → 발송 잔액 확인.
개인 파일의 기존 ax.integrations.solapi: 블록에 입력합니다.
enabled: true
api-key: '발급_API_KEY'
api-secret: '발급_API_SECRET'
sender: '사전등록한_발신번호_숫자'
channel-id는 이번 OTP SMS에서 사용하지 않습니다. 빈 값으로 유지합니다.
현재 /messages/v4/send-many/detail 실제 접수 API를 HMAC-SHA256으로 호출합니다.
국내 010/+8210 수신 번호를 지원합니다. 90바이트를 넘는 아이디 안내는 LMS로 요청하고 본문은 1600바이트로 제한합니다.
접수 응답의 실패 목록·등록 성공 수를 확인합니다. 최종 통신사 도착은 제공자 기록 및 본인 수신으로 따로 확인합니다.
번호 수신 확인이며 명의 본인확인 기관의 인증은 아닙니다.
카카오 로그인 키로 SMS·카카오 알림톡이 발송되는 구조가 아닙니다. 알림톡/템플릿 발송은 후속 단계입니다.
공식: https://solapi.com/developers/api/messages
공식 HMAC: https://developers.solapi.com/references/authentication

D. Google 로그인
Google Cloud 프로젝트에서 OAuth 동의 화면/사용자 범위를 설정합니다. 테스트 모드에서는 본인을 테스트 사용자로 추가합니다.
OAuth 클라이언트 유형: 웹 애플리케이션. 클라이언트 ID/Secret을 발급합니다.
승인된 리디렉션 URI: http://localhost:8080/login/oauth2/code/google
개인 파일 ax.integrations.google-login: enabled: true, client-id: '발급_ID', client-secret: '발급_SECRET'.
코드는 OIDC(openid/profile/email), state/nonce 검증, Google PKCE를 사용합니다.
신뢰할 수 있는 검증 이메일은 추가 이메일 OTP를 생략할 수 있으나 휴대전화 OTP는 별도로 진행합니다.
공식: https://developers.google.com/identity/openid-connect/openid-connect

E. 카카오 로그인
Kakao Developers에서 앱과 REST API 키를 준비하고 카카오 로그인 상태를 ON으로 설정합니다.
REST API 키의 클라이언트 시크릿을 확인합니다. 현재 발급 키는 기본 활성화되는 시크릿을 함께 입력합니다.
Redirect URI: http://localhost:8080/login/oauth2/code/kakao
요청하는 동의 항목: profile_nickname, account_email. 실제 제공 가능한 권한/동의 설정을 확인합니다.
이 개발 버전은 카카오 일반 OAuth2 사용자 정보 방식을 사용합니다. 카카오 OpenID Connect는 요구하지 않습니다.
개인 파일 ax.integrations.kakao-login: enabled: true, client-id: 'REST_API_키', client-secret: '클라이언트_시크릿'.
이메일의 유효·검증 표시를 확인한 경우에만 이메일 OTP를 생략합니다. 미제공·미검증이면 직접 입력하고 OTP를 진행합니다.
공식 설정: https://developers.kakao.com/docs/ko/kakaologin/prerequisite
공식 REST: https://developers.kakao.com/docs/ko/kakaologin/rest-api

F. 네이버 로그인
Naver Developers에서 애플리케이션 등록 → 네이버 로그인 API → 웹 서비스 URL/콜백을 등록합니다.
서비스 URL: http://localhost:8080
Callback URL: http://localhost:8080/login/oauth2/code/naver
이메일·이름·휴대전화 제공 항목을 설정하고 테스트 가능한 사용자를 등록합니다. 공개 이용에는 제공자 검수 조건을 확인합니다.
개인 파일 ax.integrations.naver-login: enabled: true, client-id: '발급_ID', client-secret: '발급_SECRET'.
제공자 고유 id로 계정을 구분합니다. 이메일이 같다고 EMAIL/다른 SNS와 합치지 않습니다.
현재 네이버 이메일은 검증 여부를 신뢰 표시하지 않아 별도 이메일 OTP를 진행합니다. 휴대전화도 OTP를 진행합니다.
공식: https://developers.naver.com/docs/login/api/api.md

G. 가입 검수
설정 후 앱 재시작 → /login → 가입 → 본인 이메일/휴대전화 실수신 → 6자리 OTP → 약관 확인 → 가입.
중복 SNS는 기존 계정 로그인 선택 화면을 제공합니다. 정지·탈퇴된 계정으로 새 계정을 생성하지 않습니다.
같은 이메일이어도 EMAIL과 SNS는 별개입니다. 이메일 중복은 EMAIL 자격증명 안에서만 비교합니다.
외부 제공자 오류 시 성공으로 표시하지 않습니다. 값·콜백·동의 권한·발신번호·잔액·제공자 기록을 확인하세요.
API Key/Client Secret/앱 비밀번호/OTP를 대화나 Git에 복사하지 말고 개인 파일과 전용 입력창을 사용합니다.

H. 아직 값만 넣어도 동작하지 않는 예약 영역
openai, cafe24, toss, document-editor, hwp 및 solapi.channel-id는 이번 단계의 실제 업무 연동이 아닙니다.
해당 enabled: false를 유지합니다. 원문 문서·엑셀 처리, 알림톡, 결제, 편집 엔진은 후속 단계입니다.
