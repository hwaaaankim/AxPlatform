AxPlatform 0.5.0 공통 기반 개발 정의

상위 기획안 v1.6.2의 최종 제품 범위를 유지합니다. 아래 0.5.0 규칙은 자료 저장·작업 연결·활동 집계·AI 사용량에 관한 최신 결정입니다. 기획안의 다른 요구를 구현 완료로 간주하지 않습니다.

데이터 계층
회원 account → 소유 Workspace → 사업 BusinessScope → 업무 종류(EXCEL, WORD, HWP, PPT, CRM, CALENDAR, APP) → 독립 작업 ap_work_draft.
사업 공통 COMMON은 해당 사업에서 재사용. WORKFLOW는 해당 사업의 같은 업무에서 재사용. PROJECT는 한 작업에만 연결. 원본은 ap_asset 한 건으로 저장하고 ap_draft_asset 연결을 통해 재사용하며 자동 복사하지 않습니다.
작업 복제는 다른 작업 전용 원본을 승계하지 않습니다. 공통/업무 공통 자료의 연결만 승계합니다. 엑셀 빈 양식 재사용은 기존 데이터 행을 제외합니다.

물리 경로
{root}/members/{accountId}/{COMMON 또는 workflow}/businesses/{businessId}/{common 또는 workflow 또는 projects/{draftUuid}}/{purpose}/{yyyy}/{MM}/{dd}/{assetUuid}.{확장자}
회원 ID는 DB의 불변 숫자 식별자입니다. 로그인명·이름 변경으로 경로가 달라지지 않습니다. 관리자도 동일한 규칙입니다. 자료 관리 첫 방문 또는 업로드 때 7개 업무 폴더와 COMMON을 준비합니다. 사업·작업·날짜 하위 폴더는 실제 저장 때 생성합니다.
날짜는 원본 등록일의 한국 날짜입니다. 기존 자료 이전도 원래 등록일을 유지합니다. PHOTO=사진 원본, IMPORT=엑셀/CSV 원본, SOURCE=참고, OUTPUT=명시 보관한 결과, OTHER=기타.
고객에게 실제 디스크 경로를 전달하지 않습니다. 관리자 전용 목록만 경로와 원본 존재 여부를 표시합니다. 사용자 파일명은 경로에 사용하지 않고 UUID 이름을 사용하며 링크·경로 이탈을 거부합니다.
저장소 식별 파일 storage-volume.id와 DB의 환경/루트 바인딩이 다르면 시작을 중지합니다. 파일과 DB를 같은 시점에 백업·복원합니다.

운영 데이터
ap_usage_policy: 회원 저장·AI 허용·월 토큰·월 USD 한도와 버전.
ap_ai_call: 외부 생성 호출별 예약·확인·미확인·수동 정산 기록. 성공한 제안만 집계하는 구조를 폐기합니다.
ap_model_price: 변경 불가 단가 이력. 요청 시작 시 단가 ID를 고정합니다.
ap_activity_event: 주요 페이지 방문·서버 확정 행동·실패, 회원/사업/작업/업무, 소요 시간, 안전한 오류 코드. 원문 프롬프트·자료·암호·키·쿠키·연락처·IP를 분석 로그에 저장하지 않습니다.
ap_operations_audit: 한도·단가·정산·영구 삭제·이전 변경 이력과 사유.
ap_storage_copy: 이전 후 남긴 원본 사본. 정리 검증 및 고객 영구 삭제와 연결.
ap_storage_binding: 환경·루트·저장소 식별값.

AI 비용 및 예약
매 생성 호출 전에 Responses input_tokens API로 실제 입력을 계산합니다. 계산 실패 시 생성 호출을 전송하지 않습니다. 입력 합계 + 최대 출력으로 토큰을 예약하며 입력 단가는 일반/캐시 읽기/캐시 쓰기 중 최댓값을 사용해 비용 상한을 예약합니다. 회원 행과 전역 설정 행 잠금으로 동시 예약을 직렬화합니다.
확인된 입력은 일반 + 캐시 읽기 + 캐시 쓰기로 분리해 계산합니다. 추론은 출력의 부분집합이므로 한 번만 계산합니다. 금액은 USD 소수 여섯 자리 올림입니다.
응답의 usage는 제안 검사와 취소 확인 전에 기록합니다. 누락/타임아웃/서버 중단은 UNKNOWN으로 남고 예약을 유지합니다. 미확인 호출은 이전 달 건도 다음 입장 검사에서 예약량을 유지합니다. 자동 유료 재시도는 없습니다.
운영자가 제공사 기록과 사유를 확인한 뒤 정산하면 실제 값으로 교체하고 이력을 남깁니다. 비용은 입력한 단가의 추정치이며 제공사 청구서·환율·세금·외부에서 같은 키로 쓴 비용과 같다고 주장하지 않습니다.

확장 계약
새 업무 엔진도 ManagedStorage/AssetService/UsagePolicyService/ActivityRecorder/AiMeteringService를 재사용합니다. 별도 로컬 업로드 폴더나 자체 비용 계산기를 만들지 않습니다. 작업 ID·사업 ID·현재 서버 권한을 모두 확인합니다. AI 선택 자료와 작업 첨부 자료를 분리하고 전송 전 확인을 유지합니다.
향후 형식 추가는 확장자 허용만으로 완료하지 않습니다. 원본 검증·크기 제한·읽기 어댑터·미리보기·AI 전달 정책·내보내기·회귀 검사를 함께 추가합니다.
순서형 UX: 시작 방식 → 새 파일/이전 자료 선택 → 원본 확인 → 편집/AI 제안 검토 → 저장 → 목록/대시보드 → 다시 편집. 각 단계의 빈 상태·실패·취소·부분 성공·재시도·충돌·권한/용량 부족을 실제 동작으로 구현합니다.
