AxPlatform v0.4.1 화면 배치 수정 안내
기준: 이 대화에서 제공한 v0.4.0 소스

1. 적용 방법
1) 실행 중인 AxPlatform을 종료합니다.
2) ZIP 안의 AxPlatform 폴더를 열고, 그 안의 src / qa / docs / pom.xml을
   기존 프로젝트의 pom.xml이 있는 위치에 같은 경로로 덮어씁니다.
3) 일부 HTML만 선택해서 복사하지 마세요. 공통 조각 이름이 바뀌었으므로
   포함된 templates 폴더 전체를 함께 반영해야 합니다.
4) Eclipse에서 프로젝트 새로 고침(F5), Project > Clean 후 다시 실행합니다.
   JAR로 실행하는 경우 Maven package로 새로 빌드한 JAR를 실행합니다.
5) 브라우저에서 Ctrl+F5로 새로 고칩니다.

DB 변경 및 추가 SQL: 없음.
application.yml / config/application-private.yml 변경: 없음.
이 ZIP에는 비밀번호·API 키·개인 설정 파일을 넣지 않았습니다.
v0.4.0이 이미 적용된 프로젝트에 덮어쓰는 수정본이며 최초 설치용 전체 소스는 아닙니다.

2. 확인된 원인
- 관리자 페이지의 'header' 조각 선택 이름이 HTML header 태그 선택과 겹쳐
  실제 렌더링 결과에 상단바와 AxPlatform 로고가 각각 3개씩 출력됐습니다.
  그 결과 공개 로그인 상단바가 관리자 메뉴 위를 가렸습니다.
- 76px / 66px로 나뉜 헤더 높이, 본문 시작 여백, 사이드메뉴 시작 위치를
  별도로 관리하여 화면 폭에 따라 위치가 어긋날 여지가 있었습니다.
- 큰 화면의 본문 최대 폭과 중앙 정렬 때문에 사이드메뉴 옆에 큰 여백이 남았습니다.
- grid 간격과 카드 하단 margin이 겹쳐 카드 행 사이가 과도하게 벌어졌습니다.

3. 수정 범위
- 관리자 / 업무 / 공개 화면의 공통 조각 이름 및 호출 구문을 명확히 분리했습니다.
- 상단바와 로고를 화면당 하나로 제한했습니다.
- 헤더 높이는 PC 60px, 모바일·태블릿 56px로 통일했습니다.
- 본문과 사이드메뉴가 같은 높이 변수를 사용하도록 정리했습니다.
- 본문 바깥 여백은 PC 18~20px, 모바일·태블릿 12~16px입니다.
- 넓은 화면의 불필요한 본문 최대 폭 제한을 제거했습니다.
  비밀번호 변경 같은 단일 폼은 읽기 편한 최대 폭을 유지합니다.
- 관리홈 지표 카드, 바로가기 카드, 페이지 제목, 패널·폼·탭 간격을 줄였습니다.
- 업무 홈 소개 영역, 작업 선택 카드, 단계 버튼, 업로드·편집·분석 패널도 정리했습니다.
- 모바일 메뉴의 닫힌 상태 키보드 접근을 막고, 짧은 화면에서는 메뉴 내부를 스크롤합니다.
- 메뉴 열기/닫기, Esc, 배경 클릭, PC 화면 전환 시 스크롤 잠금 해제를 보강했습니다.
- 표는 표 영역 안에서 스크롤하고, 폼/그리드/긴 문구 때문에 페이지 전체 폭이
  불필요하게 늘어나지 않도록 최소 폭과 줄바꿈을 정리했습니다.
- 시스템 상태의 버전 표시를 0.4.1로 갱신하고 SQL 이력 표에 스크롤 영역을 적용했습니다.
- CSS와 공통 JS URL 버전을 올려 이전 캐시와 구분했습니다.

4. 검증 결과와 한계
- 실제 프로젝트에 포함된 Thymeleaf/Spring 라이브러리로 27개 화면 변형을 렌더링했습니다.
  관리자, 로그인·가입·복구, 업무 홈, 업무 7종, 오류 화면을 포함합니다.
  헤더를 사용하는 화면은 상단바·로고가 각각 1개임을 확인했습니다.
- DOM 동작 검사 24개 통과:
  엑셀 준비·편집·저장·분석 및 튜토리얼 12개, 업무 목록 4개,
  로그인 3개, 관리자 모바일 메뉴 5개.
- 320 / 375 / 650 / 768 / 950 / 1024 / 1200 / 1440 / 1836px의
  9개 폭에 대해 CSS 미디어 조건, 공유 높이, 본문 시작 위치, 카드 간격을 검사했습니다.
  이 검사는 미디어 조건과 CSS 변수를 해석한 정적 스타일 검사입니다.
- 실제 Chromium은 이 작업 환경의 socket 실행 제한으로 시작하지 못했습니다.
  따라서 브라우저 스크린샷·실제 픽셀 배치·모바일 터치 검증은 완료하지 못했습니다.
- 이번 변경에서 Java 업무 로직과 DB는 변경하지 않았고 Maven 전체 테스트는 재실행하지 않았습니다.
  기존 V004UiContractTest에는 전체 라우트의 헤더·로고 중복 방지 검증을 추가했습니다.

5. 적용 후 확인할 화면
- /admin: 로고가 한 줄만 표시되고, 첫 메뉴와 관리홈 제목이 가려지지 않는지.
- /admin/members, /admin/permissions, /admin/system: 긴 목록·표는 내부에서 스크롤되는지.
- /dashboard 및 각 업무 단계: 폼·카드 사이 간격, 편집 표 내부 스크롤, 저장 버튼 위치.
- 좁은 화면: 메뉴 열기 → 메뉴 스크롤 → Esc/배경 클릭으로 닫기.
- 메뉴를 연 상태에서 화면을 넓혔을 때 본문 스크롤이 정상으로 돌아오는지.
- 사용 안내를 다시 열었을 때 이전·다음·닫기 버튼이 화면 안에서 사용 가능한지.
