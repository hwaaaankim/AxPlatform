AxPlatform v0.3.0 목표 재점검 — 구현 계약과 후속 검수
기준: 실무개발기획안·개발마스터프롬프트 v1.6.2, 사용자 2026-10-20 요청
문서 대조·코드 구현은 실제 서비스·사용성 검증 완료와 구분합니다.

1. 목표와 v0.2.0의 차이

목표는 업무를 고르면 안내 → 필요한 질문 → 이해한 내용 확인 → 내 자료 기반 미리보기 → 정밀 수정 → 저장/출력으로 이어지는 플랫폼입니다. 쉬운 시작과 정확한 값·열·행을 직접 수정하는 자유도를 함께 제공해야 합니다. 빈 채팅창에 긴 프롬프트를 요구하거나 고정 설문만 반복하는 방향은 맞지 않습니다.
근거: 기획 1.4, 3.2~3.3, 3.12~3.17 / 마스터 3·17 / GUIDE-01~04, EASE-01~12.

v0.2.0은 인증·회원·사업 범위·정책·첨부·공통 답변 초안이 중심입니다. DraftService의 다섯 답변은 저장되지만 실제 GPT 호출·사진 해석·엑셀 셀 데이터·XLSX 출력은 없습니다. 일곱 메뉴가 있다는 사실을 일곱 최종 업무 엔진 완료로 해석해서는 안 됩니다.

2. 이번 개선의 구현 계약

[GUIDE-01~04 / 기획 3.2~3.3·3.12, 마스터 3]
업무별 쉬운 선택지와 예시로 시작하고 현재 답으로 제안을 요청합니다. 확인된 내용·추정·남은 질문·경고를 분리하고 중요한 미확인 항목은 반영 전에 확인합니다. AI 결과는 summary/confirmed/assumptions/questions/draft/sheet/warnings/ready의 허용된 구조로 검증합니다. 공통 초안의 목적·자료·결과·조건·대상을 유지하며 다른 제안은 이전 제안을 남기고 요청합니다.
연결: templates/workspace/draft.html, static/js의 draft·guided-ai·workflow-guide 모듈, com.axplatform.ai, ap_ai_run.
판정: 실제 고객의 질문 생략·완료 시간·반복 사용 시험은 후속입니다. 구현했다고 타사보다 편하다는 우월성을 측정한 것으로 쓰지 않습니다.

[AI 서버 경계 / 기획 6.2~6.3·12.5~12.6·12.10, TENANT-01·PERM-04·08]
Java 서버가 Responses API를 호출하고 read_workflow_guide/read_current_draft/read_current_sheet/propose_workflow 도구만 실행합니다. 임의 SQL·명령·클래스·URL 실행을 허용하지 않습니다. 이것은 서버 내부의 제한된 도구 실행 계층입니다. 외부 MCP 클라이언트와 통신하는 공개 MCP 프로토콜 서버를 구축한 것으로 표시하지 않습니다.
실제 키는 config/application-private.yml 한 곳의 서버 설정에만 입력합니다. 모델·추론 강도·시간/횟수/자료·동시 작업 제한은 기본 설정과 빈 양식으로 제공합니다. 선택한 본인 사업의 허용 PNG/JPG/TXT만 전달하며 파일 경로·disk_key·다른 사업 원문을 모델 입력에 넣지 않습니다. PNG/JPG는 실제 이미지 입력이며 읽지 못한 값은 확인 질문으로 남깁니다.
외부 요청 동안 DB 트랜잭션/정책 잠금을 유지하지 않고 각 도구·다음 요청·저장·반영 전에 계정/세션/현재 권한을 재검사합니다. 작업 ID·멱등 키·버전·실제 상태를 저장하고 유료 요청은 자동 재시도하지 않습니다.
이번 API의 READY는 ‘검수 가능(아직 미반영)’입니다. 기획 6.3의 사용자 확인 완료 READY와 혼동하지 않고 실제 반영은 APPLIED로 구분합니다. 취소는 이미 발생한 공급자 비용이나 전송된 바이트의 반환을 뜻하지 않습니다.
판정: 실제 키로 API/사진·네트워크 장애·재시작·권한 철회 경합 시험 전에는 외부연동 미검증입니다. 실행 횟수 제한을 결제·실제 원가정산·완전한 UsageLedger 완성으로 표현하지 않습니다.

[UX-PREC-02 / 기획 3.8·3.14~3.15·12.6, EASE-05·08]
미리보기와 선택 반영을 분리합니다. 선택한 제목/답변/표만 현재 권한과 기준 버전을 검사해 함께 반영하고, 오래된 AI 결과로 새 수동 수정을 덮어쓰지 않습니다. 제안 취소는 이전 수동 입력/저장본을 유지합니다. 표의 서버 되돌리기는 별도 버전 검사와 실제 변경 권한을 사용합니다. AI apply 하나로 열·행·셀 수정 권한을 우회하지 않습니다.
판정: 중복 반영·동시 저장·서로 다른 취소의 독립성은 실제 DB·브라우저에서도 검수해야 합니다.

[EXCEL-MANUAL-01·APPLY-01·FILE-02 / 기획 7.2·7.5~7.7]
직접 입력은 AI 없이 열/행 편집 → 검증 → DB 저장 → 재조회 → XLSX 다운로드로 이어집니다. AI와 수동 입력은 동일 SheetRules를 사용합니다. 안정된 열 ID와 TEXT/NUMBER/DATE·단위·열 폭을 저장하고 앞자리 0 코드는 TEXT로 보존합니다. 음수·소수·ISO 날짜를 검증하며 오류를 0이나 절댓값으로 고치지 않습니다.
실제 데이터 다운로드와 열만 있는 빈 입력 양식 다운로드를 분리합니다. 두 파일 모두 서버 확정본 기준이며 다운로드는 DB를 변경하지 않습니다. 제한은 열 20개/행 200개/셀 2,000자/숫자 유효숫자 15자리입니다. 모든 Excel 기능이나 대규모 그리드를 지원한다고 표시하지 않습니다.
연결: ap_sheet, com.axplatform.sheet, SheetApiController, static/js/sheet-editor.js.
판정: 기본 표 기능은 이번 범위이며 전체 P2 완료가 아닙니다. Excel/LibreOffice 실제 재열기·표시/숫자·한글·빈 양식 확인은 별도 실제 앱 검수입니다.

[EXCEL-PHOTO-01·CHAT-01 / 기획 7.3~7.4]
원본 이미지/텍스트를 GPT에 전달하고 헤더와 추출 행을 같은 제안 모델로 검토합니다. 자료 없는 채팅은 고객/매출 데이터를 만들어 넣지 않습니다. 추가 대화와 현재 제안 선택을 분리하고 선택한 제안·현재 기준 버전만 반영합니다.
판정: 원본 영역과 셀의 좌표 연결, 전표 중복 탐지, 회전/페이지 편집, 승인/보류 행 단위 집계는 후속입니다. 이미지 API 구현만으로 EXCEL-PHOTO-01 전체 통과라고 쓰지 않습니다.

[PERM-01~10 / 기획 5.6~5.7·12.10·14.4~14.10]
신규 12개를 ActionRegistry에 등록합니다. AI run/read/apply/cancel, 표 read/update/export, 열 구조/행 추가/행 삭제/셀 수정/빈 양식 export를 분리합니다. V003은 카탈로그와 필수 의존만 추가하고 현재 정책 버전·등급 배정·회원·결제·관리자 암호를 변경하지 않습니다. 고객 등급에는 자동 배정하지 않습니다.
관리자는 본인 ADMIN_TEST 공간에서 구현 기능을 시험합니다. 고객 사용은 권한관리에서 해당 등급에 필요한 의존 행동과 함께 명시 배정·적용해야 합니다. 상태·표시명·관리자 전용 등 정상 제한과 미연결/미사용 초안 삭제를 보존합니다. 신규 서버 행동의 필수 의존은 ActionRegistry.requiredDependencies에서 관리하고 카탈로그 저장 시 제거를 차단합니다. 추가 의존은 허용합니다. 미구현 excel.* 준비 항목과 이번 workspace.sheet.* 구현 행동을 혼동하지 않고 후속 연결 시 기존 코드 의미를 바꾸지 않습니다.

[UI-TECH-01~05 / 기획 3.4·12.11]
Spring MVC/Thymeleaf 최초 HTML과 일반 JS 모듈을 유지합니다. 기본 실행에 npm이나 별도 프런트 서버를 요구하지 않습니다. CSRF/세션·현재 권한, 텍스트 이스케이프, 입력/버전 보존, 비동기 상태를 유지하며 가짜 진행률이나 성공 메시지로 실제 저장을 대신하지 않습니다.
판정: 브라우저·모바일·한글 IME·키보드·포커스 복귀·실시간 충돌은 문법 검사와 별개의 실행 검수입니다.

3. DB 보존과 설치 오류 재발 방지

현재 V001/V002 31개 테이블에서는 06_V003__ai_and_sheet.sql만 추가 실행하고 07_VERIFY_V003.sql로 확인합니다. 이번 업데이트 절차에서 DB 재삭제나 V001/V002 재실행을 하지 않습니다.
ap_ai_run(26컬럼)과 ap_sheet(8컬럼)을 추가하므로 수정 없는 신규 환경은 총 33개 테이블입니다. BIGINT 계정/사업 FK와 (account_id,request_key) 유일성을 사용하며 기존 문자열 draft FK의 정렬 규칙에 의존하지 않습니다. 두 테이블에 InnoDB/utf8mb4_unicode_ci, 요청 키에 utf8mb4_bin을 명시합니다.
V002 CREATE 19개에도 앞서 수정한 fresh SQL과 같은 COLLATE를 명시하여 신규 설치의 부모/자식 정렬 불일치를 줄입니다. V001 원본은 보존합니다. 기존 테이블을 강제 변환하는 SQL은 추가하지 않습니다.
V003 마커는 마지막 쓰기이며 필수 테이블·컬럼 타입/길이/NULL·PK/FK/정확한 유일 키·binding·의존 존재 시에만 생성합니다. P1SchemaCheck(-10) 다음 P3SchemaCheck(-9)가 bootstrap(0) 전에 스키마/서버 등록 누락과 연결된 행동의 필수 의존 누락을 안내합니다. 정상 카탈로그 비활성/보관·관리자 전용·미연결/미사용 초안 삭제 때문에 앱 기동을 막지 않습니다. DDL은 암묵 커밋 대상이므로 전체 스크립트가 원자 롤백된다고 안내하지 않습니다. 첫 SQL 오류에서 멈추고 확인 파일을 실행합니다.
판정: 실제 MariaDB 설치 성공은 정적 검사만으로 검증되지 않습니다.

4. 후속 우선순위 — 이번 완료로 표시하지 않을 항목

1) 전체 P2: XLSX/CSV/PDF 업로드 헤더 매핑, 추가/전체 교체 미리보기·원자 적용·멱등/복구 스냅샷, 제한 수식 엔진·실제 셀 수식/재계산·참조 유지, 분석 기준→열/셀→서버 집계→그래프/저장 보기. 근거 7.7~7.13·12.7, EXCEL-FILE-01·FORMULA-01, ANALYSIS-01~05.
2) 다중 양식의 구조만 복제/실제 행 포함 여부, 내 양식 버전·추천·선호 범위·사업 재연결을 분리합니다. 이번 EXCEL 초안 복제는 열 구조만 새 초안으로 복사하고 실제 행/행 ID는 복사하지 않습니다. 내 양식의 버전/추천·데이터 포함 선택 복제는 후속입니다. 근거 3.16·6.6~6.7, REUSE-01~03.
3) CRM 필드/고객/보기·조건 시험·거래처 ID, 일정 반복/예약/취소·발송, Word/HWP/PPT 글·표·도형 직접 편집/실제 포맷 저장·재열기, 프로그램 부품·불변 V1/V2·실행 패키지는 공통 AI 업무 제안과 별개 엔진입니다. 이번에는 업무 요약·제안까지만 지원합니다. 근거 8~11장·12.8, 마스터 17 P3/P4/P6.
4) 사용량 원자 예약·실제 원가/고객 차감·공급자 부분 실패/취소 대사·과금, 고객별 암호화된 연결·발송/결제는 P5 검수입니다. 근거 5.2~5.3·13장, BILL-01~02.
5) 실제 파일 열기·MariaDB/Eclipse·동시 실행/재시작·보안/백업 복원과 최초/재사용 완료율·시간·오류 비교를 수행합니다. 미실행은 미실행으로 유지합니다. 근거 15.5·16장, USABILITY-01/EASE-12/UI-TECH-04.
