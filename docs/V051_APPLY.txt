AxPlatform 0.5.1 적용 안내 — 2026-10-20

적용 대상
0.5.0 파일·사용량 관리 버전 및 실제 설정파일 분리가 적용된 프로젝트의 수정 패치입니다.
프로젝트 전체를 새로 만드는 ZIP이 아닙니다. 기존 프로젝트와 개인 설정을 유지하고 아래 파일을 덮어씁니다.

이번 AI 실패의 확인 결과
제공된 설정의 키로 OpenAI 모델 조회(GET /v1/models/gpt-6-astra)를 한 번 실행했습니다.
응답은 HTTP 401 / invalid_api_key / invalid_request_error였습니다.
현재 제공된 키가 인증을 통과하지 못합니다. 키 폐기·삭제·복사 오류 중 어느 경우인지는 이 응답만으로 구분할 수 없습니다.
사용자 PC가 다른 키나 다른 프로파일 설정을 읽고 있다면 이 확인 결과와 다를 수 있으므로, 패치 후 관리자 진단으로 해당 서버의 설정을 확인하세요.
인증 실패 상태에서는 모델 사용 권한이나 실제 생성 성공 여부를 검증할 수 없습니다.
모델 이름을 임의로 바꾸는 것으로 해결되지 않습니다. 패치에도 모델 변경은 포함하지 않았습니다.

적용 순서
1. 실행 중인 AxPlatform을 종료하고 기존 프로젝트를 백업합니다.
2. ZIP의 AxPlatform 폴더 안 내용을 기존 pom.xml이 있는 폴더에 덮어씁니다.
   src/main/java, src/main/resources와 pom.xml을 모두 적용해야 합니다.
   src/test, qa, docs는 검증 및 안내 파일입니다.
   압축에는 기존 application.yml, dev/test yml, application-private.yml을 넣지 않았습니다.
   개인 설정·DB 연결·D드라이브 저장 경로를 그대로 유지하세요.
3. OpenAI 프로젝트에서 사용할 유효한 API 키를 발급받아 다음 한 항목을 교체합니다.
   파일: 프로젝트 루트/config/application-private.yml
   항목: ax.integrations.openai.api-key
   마크다운 기호·공백·개행 없이 실제 키 문자열을 넣습니다. 다른 비밀값이나 DB 설정은 변경하지 않습니다.
4. Eclipse에서 프로젝트 Refresh → Maven Update Project → Project Clean 후 기존 dev 또는 test 프로파일로 재시작합니다.
   Maven CLI를 사용하는 환경에서는 프로젝트 루트에서 mvn clean test package로 빌드할 수 있습니다.
5. 브라우저를 Ctrl+F5로 새로고침합니다. CSS와 JS 모듈의 캐시 버전을 0.5.1로 변경했습니다.
6. 관리자 로그인 → 시스템 연결 → AI 연결 확인을 누릅니다.
   고정된 짧은 문장의 입력 토큰 확인만 요청합니다. 사용자 자료나 생성 요청은 보내지 않습니다.
   성공하더라도 실제 생성 권한·결과 품질까지 검증한 결과는 아닙니다.
   실패하면 펼쳐지는 오류 확인 정보의 HTTP 상태, OpenAI 오류 코드, 요청 식별번호를 확인하세요.
7. 엑셀 작업에서 필요한 AI 요청을 다시 실행합니다. 기존 작성 내용과 파일은 유지됩니다.

수정 내용
- 키 인증 실패, 접근 거부, 모델 접근 불가, 결제/사용 예산, 속도 제한, 입력 형식, 제공자 장애를 구분합니다.
- 실패 화면과 서버 로그에 HTTP 상태·제공자 오류 코드·실패 단계·요청 식별번호를 남깁니다.
  제공자의 원문 오류 메시지, API 키, 사용자 프롬프트/자료는 진단 로그에 넣지 않습니다.
- 실패 진단은 기존 ap_ai_run.result_json에 저장하여 작업 이력에서 다시 확인합니다.
  패치 이전 실패 기록의 세부 원인은 소급해서 복원하지 않습니다.
- 생성 전 사전 확인에서 중단한 기록은 '생성 요청 0건'으로 표시합니다.
  생성 시도 이후 사용량을 받지 못한 경우와 이전 기록은 '미확인'으로 유지합니다.
  앱의 표시를 제공사 청구서나 환불 보장으로 사용하지 않습니다.
- 관리자 연결 확인에 관리자 권한·현재 세션·CSRF 검사를 적용하고 30초 간격으로 제한합니다.
- 시스템 연결 페이지의 튜토리얼에 연결 확인 방법과 결과 확인 순서를 추가했습니다.
- 공통 layout.css로 각 페이지의 본문 열 안에서 폼·패널·안내·실패 알림·결과 영역을 100% 정렬합니다.
  AI 입력의 960px 제한, 결과의 1100px 제한, 관리자 비밀번호 본문의 780px 제한을 없앴습니다.
  열 설정의 계산식과 읽기 전용 열 ID는 각각 한 행 전체를 사용하고 설명을 해당 입력 아래에 배치했습니다.
  짧은 속성은 데스크톱 두 열/작은 화면 한 열로 정렬합니다.
  로그인 카드·대화상자·달력 등 자체 컨테이너는 용도에 맞는 크기를 유지하며 내부 요소를 맞춥니다.

DB 및 SQL
이번 패치는 DB 스키마 변경이 없습니다. 추가 SQL 파일도 없습니다.
0.5.0의 10~12번 SQL을 이번 수정 때문에 다시 실행하지 마세요.
사용자 DB에 대한 SQL 실행과 기존 파일 이동은 이번 작업에서 하지 않았습니다.
